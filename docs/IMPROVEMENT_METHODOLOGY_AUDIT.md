## Findings: evidence → fix → conclusion impact

### A-01 — CRITICAL: test-selection leakage, not independent validation

- `src/data.py:14–22` defines `train_dir = .../train` and **`validation_dir = .../test`**. `data_extractor` has only train and validation inputs (`54–75`); there is no third split.
- `src/train_xai.py:178–181,197–217` passes that test iterator to `fit(validation_data=...)`, selects with `BestBalancedAccuracyCheckpoint`, then calls final evaluation on that same iterator.
- `src/metrics.py:139–157` selects the maximum epoch balanced accuracy and restores those weights. Strict `>` selects the first tied epoch; `best_epoch` is zero-based.
- `src/run_iccad5_imbalance_ablation.py:96–130` and `src/run_iccad5_seed_replication.py:107–141` repeat the same test-as-validation → select → evaluate cycle for both condition families. `docs/ICCAD5_IMBALANCE_ABLATION.md:91–92` actually acknowledges validation/test is the unmodified test split.
- Concrete saved evidence: `results/xai/iccad5_seed_replication/training/balanced_sampling_seed1/metrics.json:15–19,32–48` labels classes `test_hs/test_nhs`, `total_val=19368`, selected epoch 7, and selected score **0.9742644878200217**, exactly the final balanced accuracy at line 12. The checkpoint-fix artifact similarly reports epoch 8 / **0.9649252215086439** (`results/xai/iccad5_checkpoint_fix/training/iccad5/metrics.json:47–72`). This is verified selection on test observations, not merely a suspicious variable name.
- Baseline distinction: `src/train_baseline.py:159–187,220–221` also monitors test each epoch but has **no best-epoch callback** and saves final weights. Monitoring is exposure, but the source does not implement epoch selection for that baseline; do not accuse it of the later callback's exact behavior. Comparison of baseline final-epoch versus later XAI best-test-epoch also has asymmetric selection.

**Fix:** keep official test files immutable; create a versioned, disjoint development validation split from official training, ideally grouped by parent layout/near-duplicate family with stratification and an overlap audit. With ICCAD5's 26 HS images, validation is intrinsically noisy: document exact HS counts, use training-only grouped inner folds or a training-only fixed-epoch policy chosen before new evaluation, and predeclare one protocol. Never silently rename the old test data “validation” and claim a fresh test. Existing official test results have already informed architecture/recipe/continuation choices; a genuinely confirmatory population-performance claim needs new unseen data or appropriately scoped nested evaluation. A prospective non-test-selected run on the already-explored benchmark is an improvement, not a retroactive clean-room holdout.

**Impact:** reported best-epoch scores are development/test-selected descriptive scores; unbiased generalization and “checkpoint fix improves held-out performance” are not established. The observed activation pathology remains a measurement of those checkpoints, but inference about prevalence and recipe superiority inherits selection and repeated test reuse.

### A-02 — HIGH: preprocessing is not identical; sample labels and explanation inputs can disagree

- Training/evaluation: `src/data.py:54–73` uses Keras directory iterators, RGB default, 224×224, rescale 1/255, nearest default; balanced loaders use `load_img` default nearest (`src/run_iccad5_imbalance_ablation.py:49–54`; replication `61–66`). No augmentation beyond rescale is configured.
- XAI: `src/xai_engine.py:105–119` RGB-converts and calls `pil_img.resize(target_size)` with no resampler, which for RGB is bicubic. Legacy `src/gradcam.py:95–124` duplicates this path. Float array inputs are quantized to uint8 at `xai_engine.py:109–113`; input values/range/channel shape are not explicitly validated.
- `src/run_xai.py:94–105,151–163,265–293` selects case type/target `pred` from **nearest** test predictions, then reprocesses with **bicubic** and predicts again, but keeps the earlier case/target label for explanations. A flip could therefore label an explanation as predicted-class when it is not the current input's predicted class. Source confirms the risk, not how many real flips occurred.
- `src/run_occlusion.py:247–281`, `src/run_geometry_analysis.py:109–121` and `src/run_tp_fp_geometry.py:75–84` load saved, already-resized `original.png`. Merely changing the loader to nearest cannot undo bicubic edge mixtures in these historical files. `run_geometry_analysis.py:49–58` also combines newly computed CAMs with cached occlusion NPYs without a checkpoint/preprocessing manifest join.
- `docs/FINAL_RESEARCH_REPORT.md:86–95,502–510,792–795` calls the inconsistency minor/immaterial based on one roughly 0.55-point aggregate ICCAD5 discrepancy. That does not validate all checkpoints, individual predictions, selected samples, gradients, or geometry. `docs/ICCAD5_IMBALANCE_ABLATION.md:228–246` already records a correction to its own extraction script; do not label all representation artifacts bicubic indiscriminately.

**Fix:** B's isolated shared preprocessing/provenance work above. Preserve paired old/new outputs, recompute probabilities/cases from the exact tensors explained, explicitly choose fixed-cohort sensitivity analysis versus reselected top-confidence cohort, and forbid cached-map mixing across provenance. Use source rasters for corrected regeneration.

**Impact:** historical XAI/geometry correspondence is conditional on bicubic-input provenance. Full-test aggregate accuracy similarity does not establish scientific invariance. Corrected case composition and map comparisons are unverified until GPU validation.

### A-03 — HIGH: class weighting is not isolated as a causal cause

- Final-report abstract asserts loss weighting is the operative cause (`docs/FINAL_RESEARCH_REPORT.md:20–22`); dataset prose asserts imbalance is the direct cause (`80–84`); the ablation headline again singles out loss weighting (`544–578`). These are stronger than the experiment supports and mutually overconfident.
- `src/run_iccad5_imbalance_ablation.py:12–16` reuses an existing weighted checkpoint rather than a fully crossed rerun. `docs/ICCAD5_CHECKPOINT_FIX.md:98–105,216–218` acknowledges a changed realized trajectory despite the same nominal seed and a CPU-only retrain. Seed equality does not establish equal initialization, stochastic trajectory, or hardware.
- `docs/ICCAD5_SEED_REPLICATION.md:97–119,244–258,282–290` records heavy HS collapse for **unweighted** seeds 101/202 (95.122% / 78.049%) and no weighted-seed replication. That directly refutes “absence of class weighting eliminates collapse.” Balanced sampling's observed 0% across tested seeds is evidence for this recipe in these runs, not proof of mechanism.
- Balanced sampling changes repeated HS exposure, NHS coverage, gradient variance and BatchNorm batch statistics, not just expected loss weights. Code uses 16 HS + 16 NHS with replacement (`ablation.py:57–86,106–119`), versus natural batches. At 86 steps, 1376 HS draws /26 ≈52.92 draws per HS per epoch and 1376 NHS draws /2716 ≈0.507 draws per NHS; natural iteration has 2742 observations, balanced 2752. BatchNorm appears at `src/model_xai.py:30,37,45`.

**Fix:** state an association of sampling recipe with measured collapse; predeclare matched-seed condition comparisons and record initial-weight cryptographic hashes, actual optimizer configuration, exposure and epoch-selection policy. Weighted seeds 101/202/303 would fill a useful exploratory gap only under an approved protocol. A repaired validation protocol requires matched corrected balanced controls; do not compare newly clean-selected weighted runs only against historical test-selected balanced checkpoints as a controlled ablation.

**Impact:** “balanced sampling has avoided exact-zero collapse in the runs examined” survives descriptively. “Class weighting caused collapse,” “imbalance caused collapse,” and a universal robust-recipe claim do not.

### A-04 — HIGH: current Grad-CAM++ is not verified as the stated higher-order method

- `src/xai_engine.py:187–195` nests first-gradient calculation inside a persistent outer tape, exits the tape, calculates `grads_2`, then asks that same tape for the derivative of `grads_2`. The operation producing `grads_2` was outside its recording context, so this is not a valid recorded third-derivative construction. Missing derivatives are silently replaced by zero (`201–205`).
- `tape.gradient(grads_1, conv_outputs)` differentiates the sum of a tensor target (vector-Jacobian product); in general it does **not** extract each element's diagonal second derivative required by the documented pixelwise formula. The same distinction applies to third derivatives. The denominator then uses these tensors (`212–220`).
- The downstream ELU (`src/model_xai.py:45–46`) means one must not assume a globally piecewise-linear post-target network to excuse all higher derivatives. Conversely an exp-score Grad-CAM++ approximation would need an explicit score/derivation decision; silently replacing derivatives by powers of first derivatives is not automatically an exact fix.

**Fix:** separate algorithm-audit owner/change set; construct analytic mixed-partial and diagonal-derivative toy tests, check tape nesting/recording, finite differences where appropriate, and a trusted reference. Choose/document exact or justified approximate Grad-CAM++ and score transformation. CPU symbolic/array toy checks may be prepared now; no checkpoint neural probe under the current gate. Preserve legacy method identity and outputs; rerun corrected algorithm under a new version only after authorization. **B must not edit this algorithm.**

**Impact:** existing columns called Grad-CAM++ describe the repository's legacy implementation, not established equivalence to the published method. Its degeneracy frequency, comparative ranking and geometry results cannot be attributed solely to trained-network behavior. Claims that no implementation bug exists (`docs/TP_FP_GEOMETRY_ANALYSIS.md:395–399`; final-report `312–329`) need qualification.

### A-05 — HIGH: logit saturation and local bottleneck collapse are overgeneralized

- Current Grad-CAM and LayerCAM explicitly reconstruct and differentiate ±pre-sigmoid logits (`src/xai_engine.py:29–35,156–162,240–245`). A large absolute logit does **not** itself introduce a sigmoid-derivative factor. The explanation “saturated pre-sigmoid logits drive gradients to zero” (`docs/FINAL_RESEARCH_REPORT.md:673–687`; `docs/FINAL_ICCAD5_SYNTHESIS.md:157–170`) is not established by a high logit and sparse gradient alone.
- ReLU in dense_penultimate, pooling routes, ELU derivative magnitudes, sign cancellation in GAP and final CAM ReLU are distinct possibilities. Grad-CAM's `reduce_mean` and ReLU (`xai_engine.py:166–173`) can yield a zero map despite nonzero gradient; LayerCAM uses spatial positive weights (`252–259`). Flat saliency is not direct evidence that gradients are zero.
- Exact-zero dense activation implies bias-only output **at that input** (`model_xai.py:52–53`; `xai_engine.py:29–35`), and a local gradient may be zero. It does not prove all finite occlusion perturbations stay in the same activation region: occlusion explicitly recomputes perturbed representations (`src/occlusion.py:162–185`). Thus “no perturbation method can recover dependence” (`final report:486–494,737–745`) is too broad unless demonstrated for those perturbations.

**Fix:** D should save raw signed gradients/CAM pre-ReLU values, per-channel GAP, positive and negative contributions, dense pre/postactivations and finite-perturbation responses on the exact checkpoint/tensors, with validity fields. Report direct observations separately from mechanism hypotheses. Do not infer physical mechanism.

**Impact:** observed zero-vector states and flat maps remain distinct, valid artifact observations. Universal model insensitivity and logit-saturation causation do not follow.

### A-06 — HIGH: undefined XAI statistics are encoded as meaningful zeros/locations

- `src/occlusion.py:50–72` returns 0 for undefined Pearson/Spearman (flat map), zero-norm cosine and empty-union IoU. Those are sentinel conventions, not measured zero association. Final report `343–346` calls returning zero correct and interprets the median literally; that scientific interpretation is wrong.
- `src/xai_diagnostics.py:40–61` gives empty maps `argmax=(0,0)`, synthetic image-centre centroid and spread 0. Pooling these creates artificial peak agreement/disagreement and apparent concentration. Near-flat positive maps and rounded diagnostics have other limitations; flatness thresholds differ between modules.
- `src/geometry_features.py:106–115` uses argpartition to force exactly K pixels even on zero/tied maps. Geometry now flags degeneracy but still computes arbitrary regions (`src/run_geometry_analysis.py:145–175`), and plots still include them (`225–228,260–288`). Sparse nondegenerate maps with positive support <K also fill top-K with arbitrary zero pixels.
- `geometry_features.py:142–147,155–163` encodes empty-region or absent-junction/corner recall as 0. These must not be read as poor recall when no target exists.

**Fix:** E/F/C own their isolated validity-aware analyses: null + explicit reason for undefined quantities; method-pair available/valid/degenerate counts; separate zero mass, flatness, low dynamic range and insufficient support; support-restricted and deterministic tie-aware overlaps; exclude invalid peak/spread from scientific aggregates, retain legacy values only for traceability. Define metric and degeneracy versions. Do not count three K levels as three independent samples.

**Impact:** reported Pearson medians, peak distances, concentration and geometry effects can change without any new model inference. “No signal” is not “perfectly concentrated,” and “undefined correlation” is not “no association.”

### A-07 — MEDIUM/HIGH: geometry controls are approximate-area, and inference is exploratory

- `geometry_features.py:118–136` rounds target area to whole 32×32 tiles; at K=10/20/30%, attribution areas are 5018/10035/15053 pixels but control areas are 5120/10240/15360. All are about 2.04% larger. The claim of exact matched area (`docs/FINAL_RESEARCH_REPORT.md:221–228`) is only true **between attribution methods**, not between attribution and controls. Their spatial shapes/smoothness also differ; the control null is tile sampling, not all possible random spatial regions.
- Stable control seeds use SHA256 of benchmark/sample/K (`src/run_geometry_analysis.py:44–46,125–143`) and are shared across methods: this is a good paired design. `build_summary` uses median of per-sample differences from **control means** (`244–251`), not subtraction of the control-draw median as described in `docs/FINAL_ICCAD5_SYNTHESIS.md:94–96`.
- Exact top-confidence selection is nonrandom (`src/run_xai.py:151–163`); prediction ties lack explicit stable secondary keys. Final report acknowledges small nonrandom n and uncorrected multiplicity (`769–774`) but elsewhere says “real/significant” or categorical inability to discriminate (`375–407`). Multiple K levels/methods share images. Pixel counts or repeated levels are not biological/statistical replicates.
- Width/gap proxies are distance-to-boundary at every pixel and relative per-image percentile masks (`geometry_features.py:45–55`), not polygon widths/spacings or physical units. Empty corner/junction targets and border effects warrant eligibility/coverage reporting.

**Fix:** C/J should report actual area mismatch, optionally use exact-area controls with a predeclared spatial null, retain paired sample IDs, stratify benchmark/case and degeneracy, and predeclare multiple-testing families (e.g. metric × method × K, distinguishing planned primary versus sensitivity analyses). Use image-level/cluster-aware uncertainty, not pixel-level pseudo-replication. Report no detected TP/FP difference rather than proof of equivalence; meaningful equivalence requires a prespecified margin and adequate power.

**Impact:** exploratory raster correspondence may survive, but p-values and universality cannot be carried forward unchanged; no geometry-to-physics causal conclusion is licensed.

### A-08 — MEDIUM: labels/formulas mostly correct, but metadata/report claims drift

- `src/metrics.py:15–53` correctly treats HS=0 as positive and computes BA=(HS recall+NHS specificity)/2. Keras native positive label is 1=NHS (`src/train_xai.py:53–61`), so epoch TP/TN meanings are swapped relative to reported HS-positive counts. BA is invariant under class swap, so **this is not a BA computation bug**. Validate threshold tie semantics (`>=0.5` in `train_xai.py:153` versus framework-native counters) if an output is exactly 0.5; use one explicit evaluation convention and persist HS-labelled epoch counts.
- Final-report claim BA is inflated by extreme imbalance (`290–293`) is incorrect: class prevalence drives ordinary accuracy/precision trade-offs but BA weights classes equally. A one-HS error on 41 HS changes BA by ~1.2195 percentage points; low precision can coexist with high BA. Report uncertainty and counts, not one headline score.
- Final report says XAI epochs=10 for all benchmarks (`135–136`), but `src/train_xai.py:41–47` and `results/xai_training/iccad1/metrics.json:23,56–63` show 5 epochs for ICCAD1 (ICCAD2 configured 5).
- Final-report XAI size “~25k–35k” (`127`) is the earlier design ambition, not the trained model: `results/xai_training/iccad1/metrics.json:37` and checkpoint-fix metrics line 37 report **128321**. `src/model_xai.py:49–53` alone has a 6272×16 dense matrix.
- True target outputs: `conv_early_2` is 224×224×16, `conv_mid_2` 112×112×24, `conv_final_2` 28×28×32 (`src/model_xai.py:27–44`). Report `123–124` and panel captions (`src/run_xai.py:216`) mistakenly use pooled early/mid shapes 112/56. Final target 28×28×32 is correct. Baseline target is a distinct 15×15 layer, not the final XAI target.

**Fix:** correct metadata/captions in a separately scoped documentation/presentation pass; derive target shape and parameter count from serialized configs, assert class maps and use confusion counts to regenerate scores. Do not change existing numbers just to match prose.

**Impact:** correct model-size/epoch/target-layer statements are necessary for replication and resource claims; label inversion does not invalidate the correctly symmetric BA metric.

### A-09 — MEDIUM: seeds are aids, not complete reproducibility; checkpoint resume is not exact

- `src/train_xai.py:344–361` and `src/train_baseline.py:238–258` seed once before a benchmark loop. The `train_one_benchmark(..., seed=...)` parameter in XAI is recorded but does not reseed inside the function. Training ICCAD5 alone versus after 1–4 consumes different RNG state while both can record seed 42. Replication/ablation do reseed inside each condition (`replication.py:105`; `ablation.py:94`).
- Training directory shuffling has no explicit generator seed (`src/data.py:59–65`). Balanced batches instead have a local default_rng, sorted paths and replacement sampling (`replication.py:69–95,119–124`). Path lists use `glob('*')` and counts use `os.listdir` (`data.py:24–27`), unlike the generator's supported-image filtering; manifests must filter/validate files consistently.
- Initial-weight absolute-sum checksum (`replication.py:114,153`) is not a cryptographic identity check, and the “must all differ” text (`195–198`) contradicts intentional same-seed cross-condition pairing. Equal-seed matched initialization should be verified equal across conditions, distinct across seed values.
- `BestBalancedAccuracyCheckpoint` restores model weights only (`metrics.py:153–157`), not optimizer slot state/iteration. Saving after restoration is suitable for inference but not an exact-resume checkpoint at the chosen epoch. Missing validation counts silently skip selection (`145–146`); require fail-fast if no epoch selected.
- `requirements.txt:2–25` pins packages, but Nadam is invoked by string (`train_xai.py:51,191`) and no op-determinism enablement appears in the reviewed training entry points. `scripts/tf_gpu.sh:4–32` configures library paths; it does not enforce a GPU gate or capture a hardware/environment manifest. The checkpoint-fix doc itself acknowledges nondeterministic/different-device trajectories.
- Existing final checkpoint SHA256 is well recorded (`docs/FINAL_ICCAD5_SYNTHESIS.md:5–8`), but outputs generally identify checkpoints by paths, which is insufficient to bind all cached maps and inputs to exact runs.

**Fix:** record run/seed/split IDs, full optimizer config and learning rate, dependency/build/device/driver versions, code commit, exact command, RNG/determinism settings, class map, source manifest hash, initialization and checkpoint SHA256, selected epoch base and prediction provenance. Explicitly reseed per benchmark in a **new protocol version**, never silently claim it reproduces old loop behavior. Save weights-only inference artifacts as such or restore optimizer state too for resume. Run existence/GPU/overwrite guards before resource use. Verify data content/group disjointness; directory disjointness alone does not prove no duplicate/related clips. No duplicate-data finding is asserted without that audit.

**Impact:** numeric reproducibility across devices/order/processes is unproven; equal seeds are not evidence that historical weighted/unweighted trajectories differ only in the intended treatment.
